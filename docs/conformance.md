# Conformance harness

`test/conformance` runs Hurl's own integration test scripts
(`testdata/conformance/hurl`, vendored at tag 8.0.1 — see its `SOURCE` file)
against a binary under test through a `hurl` → sonde shim
(`test/conformance/shim/hurl`; it also sets `SONDE_DEFAULT_USER_AGENT` to a
`hurl/8.0.1` value because many oracles match the default User-Agent — an
explicit `-A` in a script still wins). The stdout oracle also reads the
`# This file was generated by sonde` line of a cookie file as Hurl's
equivalent line; nothing else is rewritten. It exists to answer one question:
how much of Hurl's own behavior does sonde reproduce, script by script, byte by
byte (modulo these two documented exceptions)?

## Running it

```sh
make conformance
```

This builds `./cmd/sonde` fresh, sets `SONDE_CONFORMANCE=1`, and runs
`go test ./test/conformance -v -timeout 60m`. Plain `go test ./...` skips
the suite (it only runs the fast, in-memory unit tests for the pattern
matcher and oracle logic in this package) — the harness is opt-in because it
builds a binary, creates a Python virtualenv, starts background servers, and
can take a couple of minutes even against a fast binary.

To validate the harness itself against the real reference implementation
instead of sonde, point it at a locally built `hurl` binary:

```sh
SONDE_CONFORMANCE_BIN=/path/to/hurl make conformance
```

### Environment variables

| Variable | Default | Effect |
|---|---|---|
| `SONDE_CONFORMANCE` | unset | `1` runs the suite; anything else, `go test ./...` only runs the fast unit tests. |
| `SONDE_CONFORMANCE_BIN` | unset | Path to the `hurl`-compatible binary under test. Unset: builds `./cmd/sonde` into a temp dir once per run. |
| `SONDE_CONFORMANCE_RESULTS` | `$TMPDIR/sonde-conformance-results.json` | Where the full per-script report is written. Deliberately outside `testdata/conformance/hurl`, which is vendored and unchanged from upstream. |
| `SONDE_CONFORMANCE_NETWORK` | unset | `1` also runs the `network` lane (scripts that reach real internet hosts, e.g. `google.com`, `hurl.dev`). Off by default so the suite works offline and CI stays hermetic. |
| `SONDE_CONFORMANCE_MIN_SEMANTIC` | unset | A percentage (e.g. `95`). If set, the test fails when the blocking lane's semantic pass rate drops below it. Left unset for now (Phase 5 will set it once the engine lands); until then the suite is report-only. |

## What it measures

Every script gets scored two ways:

- **semantic pass**: the process exit code matches, and stdout matches (if
  the script has an `.out` or `.out.pattern` oracle file — most don't check
  stdout at all, in which case this trivially holds).
- **full-oracle pass**: semantic pass, and stderr also matches (if the
  script has an `.err` or `.err.pattern` file).

An actual exit code of 255 is the reference runner's own skip signal (an
unmet prerequisite, e.g. "this curl build lacks HTTP/2") and is recorded as
skipped, not pass or fail. This mirrors `integration/test_script.py` in the
Hurl repository, which the harness's oracle logic (`test/conformance/oracle.go`,
`test/conformance/pattern.go`) is a direct Go port of, including its
`<<<regex>>>` line-pattern syntax and its curl-debug-log filtering.

## Lanes

Scripts are classified into lanes (`test/conformance/lanes.go`) by what
environment they need, combining a small explicit table with heuristics
over the script and the `.hurl` files it feeds to `hurl` (including
`--glob` expansion):

- **blocking** — needs only the plain HTTP server on `:8000`. This is the
  lane that should be at or near 100% pass rate; it is the one a future
  `SONDE_CONFORMANCE_MIN_SEMANTIC` gate would watch.
- **extended** — also needs the TLS servers (`:8001`–`:8003`), the
  Unix-socket server, an IPv6 listener (`::1:8004`), or the local squid
  proxy (`:3128`). The proxy is optional: if `squid` is not on `PATH`, the
  two proxy-dependent scripts are skipped (not failed) and everything else
  in the lane still runs.
- **network** — the script or one of its `.hurl` files makes a request to a
  host other than `localhost`/`127.0.0.1`/`::1` (e.g. `tests_ssl/live.sh`
  hits `google.com`). Skipped unless `SONDE_CONFORMANCE_NETWORK=1`. Scripts
  that redirect a non-local hostname back to `127.0.0.1` via
  `--resolve`/`--connect-to`/`--unix-socket` are correctly kept out of this
  lane (see the tests in `lanes_test.go`).
- **timing** — an explicit list of directories that sleep, retry, or rate-limit
  (`delay`, `retry`, `limit_rate`, `progress_bar`, `timeout`,
  `connect_timeout`, `bench`, `repeat`). Pulled out of `blocking` so a slow
  CI runner cannot make the headline number flaky; still run and reported.
- **unsupported** — needs tooling or files the harness does not provide.
  Currently just `tests_ok/completion/completion_bash.sh`, which sources
  `../../completions/hurl.bash` — outside the vendored tree
  (`scripts/sync-hurl-conformance.sh` only pulls `integration/hurl/`,
  `bin/requirements-frozen.txt` and `LICENSE` from upstream). There is no
  `hurlfmt` shim either, for the same reason; as of the vendored 8.0.1 tag
  no test script needs one.
- `tests_pty` is not vendored/run at all yet — those scripts need a real
  pseudo-terminal, which is a later phase.

## Servers

`test/conformance/servers.go` starts the same Python servers Hurl's own CI
does (see `bin/test/test_prerequisites.sh` in the Hurl repository): plain
HTTP on `127.0.0.1:8000`, HTTP on `[::1]:8004`, three TLS servers on
`8001`–`8003` (self-signed, CA-signed, client-cert-auth), the Unix-socket
server, and squid if available. Each server's stdout/stderr goes to
`testdata/conformance/hurl/build/*.log` (gitignored; the vendored tree
itself never changes). Before starting anything, the harness checks each
port is free and reports the owning PID via `lsof -ti` if not, rather than
silently colliding with something else already listening. Every child
process gets its own process group so teardown (`SIGTERM` then `SIGKILL`,
including on `Ctrl-C` or a panic mid-run) can't leave orphans behind.

Scripts run sequentially, under `bash`, with `cwd` set to
`testdata/conformance/hurl` (several of the vendored Python servers assume
that as their own cwd too, e.g. `app.py` globs `tests_*/**/*.py` relative to
it), stdin closed, and a 60-second per-script timeout that kills the whole
process group, not just the immediate `bash`. Output is captured through
temporary files, not pipes: piping the reference `hurl` binary's stdout
directly to a Go process can put it into uninterruptible sleep when it
detects a non-terminal stdout, and temp files sidestep that entirely.

## The Python environment

The harness creates (once) and reuses a virtualenv under
`os.UserCacheDir()/sonde-conformance/venv` (e.g. `~/Library/Caches` on
macOS, `~/.cache` on Linux), then installs
`testdata/conformance/hurl/bin/requirements-frozen.txt` into it. That file
pins exact versions but ships no hashes to verify against
(upstream doesn't publish a hash-locked variant), so this is version pinning
for reproducibility, not a verified supply chain — it exists only to run
vendored test fixtures locally and in CI, never in a production path.

## Reference-binary validation

Run against a locally built Hurl 8.0.1 binary (`cargo build --release` in a
Hurl checkout), the blocking lane passes at 100% (both semantic and
full-oracle) and the timing lane at 100%. The extended lane passes at 93.8%
(15/16 ran, 2 skipped for missing `squid`): `tests_unix_socket/unix_socket.sh`
expects the request to *fail* with a libcurl connection error (exit 3), but
the locally built binary (macOS, LibreSSL/SecureTransport) completes it
successfully (exit 0) — a platform/TLS-backend difference in the fixture
itself, not a harness bug. Run against the current (request-engine-less)
sonde build, the blocking lane sits at ~5% semantic / 0% full-oracle, as
expected for plumbing validation only.

## CI

`.github/workflows/ci.yml` runs the suite in a `conformance` job with
`continue-on-error: true`: it is report-only until Phase 5 wires
`SONDE_CONFORMANCE_MIN_SEMANTIC` to actually gate on it. The job uploads
`SONDE_CONFORMANCE_RESULTS` (`conformance-results.json`) as a build
artifact so pass rates are visible per run without re-running anything
locally.
